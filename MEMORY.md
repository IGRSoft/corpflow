## Version Tracking

- Plugin version: **4.0.31** — unreleased on `develop` (origin/master is still at 4.0.28). Closes phases A–E of the second leaderboard V1 fix plan: 21 of 26 findings, one theme. A control that fails silently is indistinguishable from one that passed, and an evidence token that asserts more than it observed is worse than none. The P0 is the shape of the whole release: a scheme with an empty test plan enumerated 49 cases, executed none, recorded `tests:49`, and the dedupe gate then refused every later attempt to run them — so a platform reached a merge decision with zero tests executed while every stage downstream read a verdict that said only "denied". Two edits close it: promotion now writes `discovered:<n>` when no outcome vocabulary is present, and the gate never suppresses against a prior that executed nothing. The durable lesson is about what a TOKEN is entitled to claim: `tests:49` was read for months as "49 tests ran" when it only ever meant "the string '49 tests' appeared", and the gap between those let a run's only real verification vanish behind a denial that looked like a control working. Second, and larger than the fix plan said: five sweep-obligated agents — QA, FN, ST, TL, ET — carried no `--facts` invocation at all, so every sweep item they emitted reached the frontmatter and stopped. That is not a wording problem, it is a hole in every run that used those stages, and it is how this run nearly lost its only blocker. PL was exempted correctly (its payload is canonical in `pl0-procedure.md`) and the exemption is now pinned by a test so it cannot decay. Third, the decisions ring's spill got a reader (`--read-decisions`): twelve decisions written for one task now all resolve, where four were previously lost in silence. Fourth, one frontmatter reader (`frontmatter-lib.sh`) shared by the boundary gate and the ledger writer, closing a divergence where a flat-shaped artifact was unreadable to one and wrote a healthy row through the other. Two findings were corrected rather than implemented: the fixplan's `stage`/`status` stub addition was already handled by `_sweep_defaults`, and F-25's premise was wrong — staged content IS inside the tree fingerprint, so committing never clears a denial; only untracked-file content is outside it. Three defects were found in this release's own work and fixed before it shipped: `yq`'s `//` silently swallowed a literal `false` in the new `test_suite_compiles` reader (turning one of three legal answers into "absent"), a `cat` over a missing spill file fired a `|| printf '[]'` fallback ON TOP of jq's output under `pipefail` (two JSON documents in one variable, reporting every evicted id as lost), and a `grep -f <(...)` process substitution silently matched nothing. All three were the same class as the findings being fixed — a failure that looks like a result.
